# Linux inference dispatch — HALO-LINUX-054

The portable base is pinned to Android
`d1c87d5895e9c68af62a652b6dbec0d3f626f0ae`: 186 production source files across the
existing seven modules. The provider/runtime source copies are unchanged Android
code, including dispatch intent, data-category provenance, revocable leases and
speech-sharing metadata. This does not implement every Android feature on Linux.

## Configuration migration

**An endpoint or API key is no longer enough to permit off-device inference.**
The Linux host now requires `inference.allow_remote: true` for HTTPS LAN and cloud
providers. Missing permission defaults to false. The setting must be a YAML boolean,
not a string, number or null. Duplicate YAML keys are rejected. Both endpoint and
model must be configured together. Credentials remain in the protected environment,
not in YAML. Existing non-loopback configurations need a deliberate opt-in.

A local endpoint remains available without that permission. Example only: select
an actual installed model rather than treating this model name as a download:

```yaml
inference:
  endpoint: "http://127.0.0.1:11434/v1"
  model: "YOUR_INSTALLED_MODEL_ID"
  allow_remote: false
```

For an operator-selected HTTPS provider, edit that same `inference` section:

```yaml
inference:
  endpoint: "https://YOUR_PROVIDER_HOST/v1"
  model: "YOUR_SELECTED_MODEL_ID"
  allow_remote: true
```

The second example is not a working provider configuration until those placeholders
are replaced. Supply `HALO_INFERENCE_API_KEY` separately if required. Consent covers
the current explicit text request and provider-check metadata, not an implicit
permission to attach memories, documents, screen content, tools, audio or images.
Text supplied by the user can itself be personal: this policy is not anonymization.

Configuration is captured for the process lifetime. Editing YAML is **not** a hot
revocation signal; stop/restart the process explicitly. Linux does not yet have
Android's independent Private/Full Power profile stores or switching UI. Shutdown
invalidates outstanding leases and calls their cancellation hooks before closing
the HTTP client. Cancellation cannot retract bytes already transmitted.

## Enforcement boundary

`LinuxProviderLifecycle.create` composes the unmodified canonical
`withProviderDispatchPolicy` HTTP guard with `LinuxRemoteDispatchPolicy`.
The current host accepts only the pinned provider ID and either INFERENCE with
exactly TEXT, or PROVIDER_CHECK with exactly ACCOUNT_METADATA. Extra categories,
unsupported operations, stale revisions, closed leases and excess leases fail
closed. Endpoint and model selection remain explicit, without provider fallback.

The canonical guard admits requests before DNS/connect and rechecks the lease at
network dispatch. Redirects are disabled. The host disables system proxies and
OkHttp connection-failure retries. DNS lookup must match the configured hostname.
`localhost` is resolved directly to 127.0.0.1; `[::1]` uses the IPv6 loopback address.
Neither uses DNS. Only `localhost`, `127.0.0.1` and `::1` receive loopback permission;
other endpoints require HTTPS and explicit remote consent. Use `[::1]` explicitly
when the local server listens only on IPv6.

No request content, credentials or provider costs are retained by the policy.
It does not introduce a second planner, tool authorization engine or activity
ledger. This is an application boundary, not an OS firewall: a separately configured
local inference server could itself forward requests elsewhere. Same-user/root
software and traffic generated by other components are outside this guard.

## Verification before installation on Trixie

The focused gate needs a Kotlin command-line compiler and Java on PATH:

```bash
/usr/bin/python3 -B -m unittest discover -s scripts -p 'test_linux_dispatch_policy.py'
```

It executes real policy/endpoint/settings Kotlin code against the canonical
interface declarations. Its second test is a source-composition check, **not** an
executed YAML or HTTP test. It does not replace these full-checkout gates:

```bash
python3 -B scripts/sync-canonical-sources.py
./scripts/preflight.sh --build
./scripts/verify-offline-source.sh
./gradlew clean build --no-daemon
./scripts/smoke-test.sh
```

Run the optional canonical-cognition gate separately when deploying that variant;
its external Android checkout must match the new pin. Do not reuse the old 050
build results as verification of this newer snapshot. Check allowed loopback
inference, blocked off-device probes without consent, approved HTTPS operation,
redirect refusal and stop-during-request behavior on the actual target.
Install/restart only after the appropriate gates pass. No service or OS setting
is automatically changed by this batch.

The separate Brain API/importer is unchanged and remains unwired into Halo.
Archive/DTO compatibility has its own pin; this batch updates the portable runtime
source pin only. Full speech adapters, role routing, Android profile UI, remote peer
pairing and live bidirectional synchronization remain separate work.
See [executed evidence and limits](HALO-LINUX-054-VERIFICATION.md).
